# T1.5 등록공장 정제 — 작업 계획서

- 상태: 진행 중
- 상위 문서: `docs/plans/M1-source-cleaning/phase-plan.md`

## 목적

- 전국 등록공장 21만 행을 정제해 공장마다 시도·시군구·산업단지 입주 여부를 뽑음
- 이름별 전국 통계(공장 수, 시도 수, 생산품 종류 수)를 만들어 T1.6의 동명 판단에 씀
- 대상 회사와 이름이 맞는 공장만 저장하는 일은 T1.6·T1.7에서 함 (여기서는 전체를 정제만 함)

## 입력

- `kicox_factories` (manifest, cp949), `pipeline.normalize`
- 사전 점검 (2026-09-28)
  - 217,048행, 읽기 3.2초
  - 회사명·생산품·주소 결측 0. 단 주소가 공백 문자뿐인 행 1,880개
  - 주소 첫 단어
    - 17개 시도 표준 이름이 대부분
    - 변형 표기: `제주특별자치`, `세종특별자치시,`, `제주도`, `강원도`
    - 도로명으로 시작하는 행 98개 (예: `동부로`)
    - `경기동로`처럼 시도 이름으로 시작하는 도로명이 있어 앞 글자만 보고 판단하면 안 됨
  - 단지명이 비어 있는 행 132,937개 → 산업단지 입주 84,111개(38.8%)
  - 이름 정규화 후 고유 회사명 151,227개

## 절차 (TDD)

1. `sido_from_address(s)`
   - 주소 첫 단어(끝 쉼표 제거)를 허용된 표기와 통째로 비교해 짧은 시도 이름(서울, 부산, …, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주)으로 바꿈
   - 허용 표기
     - `서울특별시`, `○○광역시`, `세종특별자치시`, `경기도`
     - `강원특별자치도`·`강원도`, `충청북도`, `충청남도`
     - `전북특별자치도`·`전라북도`, `전라남도`, `경상북도`, `경상남도`
     - `제주특별자치도`·`제주특별자치`·`제주도`
   - 인식하지 못하면 결측
2. `sigungu_from_address(s)`: 시도를 인식한 경우 둘째 단어가 시·군·구로 끝나면 그 값 (세종은 결측)
3. `clean_factories(raw)`
   - 열: `seq`(순번), `company_name`, `name_key`, `complex_name`(빈 값은 결측), `in_complex`, `products`, `sido`, `sigungu`
   - 주소 원문은 저장하지 않음 (화면에 필요한 것은 시도·시군구뿐)
4. `name_stats(factories)`: 이름키별 `n_factories`, `n_sido`, `n_products`
5. `load_factories()`
6. 테스트
   - 가짜 데이터: 시도 표기·도로명·공백 주소·`경기동로`, 시군구, 산단 여부, 이름별 통계
   - 원본 회귀: 217,048행, 시도 결측 1,978, 고유 이름키 151,227, 산단 입주 84,111, 17개 시도가 모두 나옴

## 진행 기록

- 2026-09-28 사전 점검에서 시도를 알 수 없는 행이 처음 예상(도로명 약 100행)보다 많은 1,978행으로 나옴
  - 원인을 확인해 보니 공백 문자뿐인 주소 1,880행이 있었음. 결측(NaN)이 아니라서 앞선 "주소 결측 0" 점검에 잡히지 않았음
- 테스트를 먼저 씀 (`tests/test_factory.py` 33개). 실행하니 `factory` 모듈이 없어 실패함 → 기대한 실패
- 구현 후 전체 143 passed (`-W error`)

  - 고유 이름키 151,227, 산업단지 입주 84,111
