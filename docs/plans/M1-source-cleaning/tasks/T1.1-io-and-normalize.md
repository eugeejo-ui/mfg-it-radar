# T1.1 원본 읽기 기반과 공통 정제 함수 — 작업 계획서

- 상태: 완료
- 상위 문서: `docs/plans/M1-source-cleaning/phase-plan.md`

## 목적

- 원본을 파일명 대신 source_id로 찾고, 원본이 바뀌면 manifest를 다시 만들 수 있게 함 (M0 일회성 스크립트 대체)
- 여러 원본에서 반복되는 정제 규칙을 한 곳에 모아, 원본별 정제(T1.2~T1.5)가 같은 규칙을 쓰게 함

## 입력

- `data/raw/manifest.csv`, `docs/data-sources.md` 2장(값 형식), SPEC 7장 정규화 규칙, SPEC 4.2장 규모 구간

## 절차 (TDD: 테스트 → 실패 확인 → 구현 → 통과 확인)

1. `pipeline/manifest.py`
   - `load_manifest()`: source_id별 항목(파일명, 인코딩, sha256, 크기 등)
   - `source_path(source_id)`: 원본 경로. 모르는 source_id나 없는 파일이면 오류
   - `verify(entry)`: sha256·크기 비교
   - `refresh()`: 파일이 바뀌었을 때 sha256·크기를 다시 계산해 manifest에 씀
   - 명령: `python -m pipeline.manifest check`, `python -m pipeline.manifest refresh`
   - `rows` 열은 등록할 때 확인한 행 수로 두고, 실제 빌드 행 수는 `source_meta`(T1.7)에 기록함
2. `pipeline/normalize.py`

| 함수 | 규칙 |
|---|---|
| `name_key` | SPEC 7장 정규식으로 법인 표기·공백 제거 + 영문 대문자화. 빈 값이면 None |
| `parse_money` | 쉼표 문자열·숫자 → float × 단위. 빈 값·`-`는 결측. 0은 0으로 둠 (0을 결측으로 볼지는 원본별 정제에서 정함) |
| `parse_date` | `YYYY/MM/DD` → 날짜. 형식이 다르면 결측 |
| `ox_to_bool` | `O` → 참, `X` → 거짓, 그 밖 → 결측 |
| `industry_label` | `제조업(10~34)` → `제조업` |
| `ksic2_from_ftc` | `C2011` → `20` |
| `ksic5_from_ngms` | `5100` → `05100` |
| `ksic2_from_ksic5` | `05100` → `05` |
| `size_band` | 반올림(0.5는 올림) 후 `300명 이하` / `300~1,000명` / `1,000~3,000명` / `3,000명 초과`. 경계값은 아래 구간에 포함 (300 → 이하, 1,000 → 300~1,000명) |

3. 테스트
   - `tests/test_normalize.py`: 표 형식, 원본 없이 돎
   - `tests/test_manifest.py`: 임시 폴더에 가짜 manifest·파일을 만들어 돎
4. `tests/test_raw_manifest.py`는 `pipeline.manifest`를 쓰도록 정리함 (동작은 같게 유지)
