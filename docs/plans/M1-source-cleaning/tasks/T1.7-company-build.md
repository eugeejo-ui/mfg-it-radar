# T1.7 회사 요약·신호와 연간 빌드 명령 — 작업 계획서

- 상태: 진행 중
- 상위 문서: `docs/plans/M1-source-cleaning/phase-plan.md`

## 목적

- T1.2~T1.6 결과를 합쳐 화면이 바로 쓰는 테이블 8개를 `data/processed/`에 씀
- `python -m pipeline.jobs.annual` 한 줄로 원본에서 결과까지 다시 만들고, 검증 게이트를 통과할 때만 파일을 씀
- 저장소가 공개이므로, 커밋되는 결과물에 개인정보가 없는지 CI에서도 검사하게 함

## 입력

- `pipeline.sources.*`, `pipeline.match`, `data/manual/*.csv`
- 대상 회사: 최신 공시연도(2026) 제조업. 전년 = 대상 연도 − 1

## 절차 (TDD)

1. `pipeline/ksic.py`: KSIC 10차 제조업 중분류(10~34) 짧은 이름(예: 20 → 화학, 26 → 전자부품·통신장비)과 정식 이름
   - 그 밖의 코드는 이름 없이 코드만 둠
2. `pipeline/signals.py`
   - `it_yoy_pct(curr, prev)`: 두 해 모두 0보다 클 때만 계산
   - `signal_tags(company)`: 고정 순서의 신호 목록
     - IT 투자 +20%: 증감률 20% 이상
     - CISO 겸직
     - 외부 보안인력: 외부인력 0보다 큼
     - 인증 없음
     - 계열 SI 없음: 기업집단 소속이 아니거나, 소속 집단에 계열 SI가 없음
     - 배출권 할당대상
     - 2개 이상 시도: 결합된 공장의 시도가 2개 이상
3. `pipeline/build.py`
   - 회사 요약 `company` (387행)
     - 회사명, 업종, 세부업종(`ksic2`: 공정위 우선, 없으면 배출권 / `ksic2_source` / 짧은 이름), 규모 구간, 임직원
     - 상장 여부(공정위 소속만, 그 밖은 결측 → M3)
     - IT 투자액·전년 투자액·증감률, IT 인력·IT 인력 비중
     - 보안 투자액·비중(B/A), CISO 임원·겸직, 외부 보안인력, 인증 목록·보유 여부, 투자 품목 원문 참조 여부
     - 기업집단 목록, 집단 소속 여부, 소속 집단 계열 SI 목록·유무
     - 배출권 할당대상
     - 공장 수·시도 목록·시도 수·다거점·산단 입주 공장 수·대표 생산품(상위 3)·동명 의심
     - 신호 태그
   - 결합 열 추가: `kisa_disclosure`·`group_membership`·`emission_target`에 `company_id`(결합되지 않으면 결측)
   - `factory`: 대상 회사와 결합된 공장만 + `company_id`, `homonym_suspect`
   - `business_group`: 계열 SI 목록·유무
   - `xwalk`, `review_queue.csv`
   - `source_meta`: 원본별 제공 기관·포털·기준일·빌드 행 수·빌드 시각(`built_at`, 앱 캐시 키로 씀)
   - `company_id`를 정하는 곳을 한 함수(`assign_company_id`)로 둠 → M3에서 corp_code로 바꿀 곳
   - 법인등록번호 캐시: `data/cache/ftc_jurir.parquet`
4. `pipeline/validate.py`: 게이트
   - 테이블별 키 고유성, 필수 열
   - 직전 결과보다 행 수가 20% 넘게 줄면 실패
   - 개인정보 열 이름(대표자·법인등록번호·사업자등록번호·jurir_no·bizr_no·ceo_nm)과 10자리·13자리 숫자 문자열 값 금지
5. `pipeline/meta.py`: `source_meta` 만들기
6. `pipeline/jobs/annual.py`: 빌드 실행, 테이블별 행 수·검수 건수·소요 시간 출력
7. 테스트
   - `tests/test_signals.py`, `tests/test_validate.py`: 가짜 데이터
   - `tests/test_build.py`
     - 조립 규칙: 가짜 데이터로 세부업종 우선순위, 공장 집계, 계열 SI
     - 원본 전체 빌드 회귀: 원본이 있을 때만
   - `tests/test_processed_privacy.py`: 커밋된 `data/processed/` 전체를 검사함. CI에서도 돎

## 산출물

- `pipeline/ksic.py`, `signals.py`, `build.py`, `validate.py`, `meta.py`, `jobs/annual.py`
- 위 테스트 4개
- `data/processed/` 테이블 8개 + `review_queue.csv`

## 검증 방법

- 새 테스트가 구현 전에 실패하고 구현 후 통과함 (`-W error`)
- `python -m pipeline.jobs.annual` 실행 → 게이트 통과, 행 수 일치
  - company 387, kisa_disclosure 1,599, group_membership 3,539, business_group 102
  - emission_target 772, factory 1,351, xwalk 952
- 두 번 연속 실행해도 결과 행이 같음

## 진행 기록

- 2026-09-28 회귀 기대값을 구현과 별도로 계산함
  - 도중에 `groupby().agg(set/list)`가 pyarrow 문자열 열에서 결과를 다시 문자열로 바꾸는 것을 발견함 → 구현에서는 목록 열을 딕셔너리로 직접 모음(`_by_company`)
- 테스트를 먼저 씀 (`test_signals`, `test_validate`, `test_build`, `test_processed_privacy`, `test_annual_job`). 실행하니 모듈이 없어 실패함 → 기대한 실패
  - `source_meta` 기대 행 수를 7로 잘못 적었다가 구현 전에 6으로 고침 (빌드가 쓰는 원본은 6개. 시도별 통계 4종은 보류 중)
- 구현 중 고친 것
  - 증감률이 딱 20%인 경우 부동소수점으로 19.999…가 나와 "IT 투자 +20%" 신호가 빠짐 → 소수 6자리 반올림 후 비교
- 첫 빌드 결과를 사람 눈으로 보다가 결합 누락을 발견함
  - CJ제일제당이 "기업집단 소속 아님, 계열 SI 없음"으로 나옴
  - 원인: KISA는 `CJ제일제당`, 공정위·공장 명부는 `씨제이제일제당`으로 표기함
  - → 결합 규칙에 "영문 표기 변환"(영문 글자를 한글 발음으로 바꾼 두 번째 키, 완전 일치가 없을 때만)을 추가함. 자세한 내용은 T1.6 문서 추가 기록
  - 변환으로 붙은 28건을 모두 눈으로 확인함 → 같은 회사의 다른 표기였음 (삼성SDI↔삼성에스디아이, LG전자↔엘지전자 등)
- SK에너지의 계열 SI에 SK C&C 사업을 하는 에스케이(주)가 빠진 것을 발견함
  - 공정위 업종코드: 에스케이(주) K6499, 포스코디엑스 M7212 → J620이 아님
  - SPEC 7장이 이름을 댄 두 곳을 `data/manual/si_manual.csv`에 사유와 함께 넣음
- 회귀 기대값을 두 변경에 맞춰 별도 계산으로 다시 구해 고침
- 연간 빌드를 실제로 3번 실행함
  - 매번 게이트 통과
  - 두 번째부터는 직전 결과와 행 수를 비교하는 검사도 통과
