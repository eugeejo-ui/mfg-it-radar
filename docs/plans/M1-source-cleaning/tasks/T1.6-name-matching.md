# T1.6 이름 결합과 대응표 — 작업 계획서

- 상태: 완료
- 상위 문서: `docs/plans/M1-source-cleaning/phase-plan.md`

## 목적

- 대상 회사 387곳에 전년 공시, 공정위 소속회사, 배출권, 공장을 이름키로 결합하고, 결합 결과를 대응표(`xwalk`)로 남김
- 사람이 고치는 덮어쓰기 파일로 자동 결합을 바로잡을 수 있게 하고, 확인할 것을 검수 목록으로 뽑음

## 입력

- T1.2~T1.5 정제 결과, `data/manual/`(이번 작업에서 머리글만 만듦)
- 사전 점검 (2026-09-28)

| 원본 | 대상과 이름 일치 | 비고 |
|---|---|---|
| 2025 공시 | 351 / 387 | 나머지 36곳은 신규 공시 또는 회사명 변경 |
| 공정위 소속회사 | 125 | 두 집단 소속 1곳. 이름 충돌 2쌍('동림', '동양에너지')은 대상과 겹치지 않음 |
| 배출권 | 142 | |
| 공장 | 334 (공장 1,351행) | 공장 20곳 이상인 이름 4곳: 대원산업 58, 우리산업 31, 태광산업 31, 에스텍 23 |

- KISA 2026 업종 결측 6곳은 모두 글로벌 IT 기업(Google, OpenAI 등)임

## 절차 (TDD)

1. 대응표 `xwalk`: 한 행 = (원본, 이름키)
   - 열: `source`, `name_key`, `source_name`(원본 표기 하나), `company_id`, `method`(이름 일치·수동), `status`(확정·검수 필요·제외), `use`(빌드에서 결합에 쓸지), `note`
   - 계획서와 달라지는 점: 상태값 "실패" 대신 "제외"(사람이 결합하지 않기로 정함)를 둠. 이름이 안 맞는 경우는 그 원본에 해당 회사가 없는 것이라 대응표에 행이 생기지 않음
2. 원본별 규칙
   - 전년 공시(`kisa_<전년>`), 배출권: 이름키 일치 → 확정
   - 공정위: 같은 이름키에 서로 다른 법인등록번호가 둘 이상이면 검수 필요, `use=False` (어느 회사인지 모름)
   - 공장: 이름별 전국 공장 수가 20곳 이상이면 검수 필요(동명 의심), `use=True`
     - 결합은 하되 화면에 "동명 회사가 섞였을 수 있음"을 표시함
     - 확정은 M3에서 본사 주소로 함
3. 덮어쓰기 `data/manual/xwalk_overrides.csv` (`source`, `source_name`, `company_id`, `reason`)
   - `company_id`가 NONE이면 해당 결합을 제외함
   - 그 밖의 값이면 수동 확정 (표기가 달라 자동으로 못 붙인 결합 추가 포함)
   - 대상에 없는 `company_id`는 적용하지 않고 검수 목록에 올림
4. 검수 목록 `review_queue`: `category`, `company_id`, `company_name`, `source`, `detail`
   - 공장 동명 의심
   - 공정위 이름 충돌
   - 전년 공시와 이름 불일치
   - 업종 결측(대상 판정 불가)
   - 덮어쓰기 오류
5. `data/manual/xwalk_overrides.csv`, `data/manual/si_manual.csv`: 머리글만 만듦. `read_manual_csv`로 읽음 (행이 없어도 열이 있는 빈 표)
6. 테스트
   - 가짜 데이터: 규칙별 사례, 덮어쓰기 4가지, 검수 목록
   - 원본 회귀: 원본별 결합 수 351·125·142·334, 동명 의심 4, 공정위 충돌 0, 전년 불일치 36

## 추가 기록 (T1.7 중 보완, 2026-09-28)

- 발견
  - T1.7 첫 빌드에서 CJ제일제당이 기업집단에 결합되지 않음
  - KISA는 `CJ제일제당`, 공정위·공장 명부는 `씨제이제일제당`으로 표기해 이름키 완전 일치가 실패함
- 보완 (TDD)
  - `normalize.translit_key`: 이름키의 영문 글자를 한글 발음으로 바꿈 (C→씨, J→제이, S→에스, K→케이 등)
  - `match._match`: 완전 일치가 먼저이고, 없을 때만 양쪽 변환 키를 비교함. 대응표 `method`는 "영문 표기 변환"
  - 변환 키가 겹치는 대상 회사끼리는 변환 결합에서 뺌
  - 테스트 9개 추가 (변환 6, 양방향 결합 2, 완전 일치 우선 1)
- 계획과의 관계: 계획은 "이름키 완전 일치만 씀, 유사도 매칭 안 함"이었음. 영문 표기 변환은 추정이 아니라 정해진 변환 규칙이라 그 원칙 안의 보완으로 봄
- 결과
  - 결합 수: 공정위 125 → 131, 배출권 142 → 145, 공장 334 → 353키(340곳)
  - 공장은 한 회사가 영문·한글 두 표기로 올라 있어 결합 키가 회사 수보다 많음
  - 변환 결합 28건을 모두 눈으로 확인함 → 같은 회사의 다른 표기
  - 영문 약어만으로 붙은 2건(DYP↔디와이피, TSE↔티에스이)은 M3에서 본사 주소로 다시 확인할 것
