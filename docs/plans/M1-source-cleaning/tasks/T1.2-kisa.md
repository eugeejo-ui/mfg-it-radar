# T1.2 KISA 정제 — 작업 계획서

- 상태: 진행 중
- 상위 문서: `docs/plans/M1-source-cleaning/phase-plan.md`

## 목적

- KISA 정보보호 공시 2개년을 한 테이블(`kisa_disclosure`)로 정제하고, 대상 회사(2026 제조업) 목록을 뽑음
- "값 없음", "0", "공시 원문 참조"를 구분해, 벤치마크에 가짜 0이 섞이지 않게 함

## 입력

- `kisa_2025`, `kisa_2026` (manifest), `pipeline.normalize`
- 사전 점검 결과 (2026-09-28)
  - IT 투자액 0 또는 결측 17행: 모두 비제조업, 대부분 글로벌 기업이 수치 대신 설명문을 씀. 이 중 실제 0(투자 없음)은 1행
  - 투자항목이 "첨부/참조" 문구인 행 5개 중 1행은 투자액이 있음 → 수치와 품목의 "원문 참조"를 따로 표시해야 함
  - 인증 칸: 영문 코드 387행, 한글 명칭만 32행, "없음"류 220행, 결측 82행
  - 업종 결측 6행은 모두 IT 투자액 0/결측 행에 포함됨 (글로벌 기업)
- 기준 연도 확인: KISA 포털 제도 안내에는 제출 기한(매년 6월 30일)만 있고 기준 연도는 없음. "직전 연도 1~12월 기준"이라는 설명은 2차 자료에만 있어 확정하지 못함 → 데이터에는 공시연도만 저장함

## 절차 (TDD)

1. 열 이름을 영문 snake_case로 바꿈 (화면 용어는 앱에서 붙임)
2. 규칙
   - 금액: 원 단위 float (`*_krw`)
   - 여부 열: `ox_to_bool`
   - 자율/의무: 의무 → `mandatory=True`
   - 업종: `industry_label`
   - `정보보호 공시 우수기업` 열(전부 X)은 버림
   - `figures_in_attachment`: IT 투자액이 결측이거나, 0이면서 [총임직원이 0·결측이거나 투자항목·특기사항에 첨부·참조·참고·추가 기재·글로벌 문구가 있음] → 투자액·인력 수치를 결측으로 바꿈 (가짜 0 제거)
   - `items_in_attachment`: 투자항목이 첨부·참조·참고·추가 기재를 가리킴 → 화면 "공시 원문 참조"
   - 투자항목이 `0`, `-`, `.`, `없음`, `해당사항 없음`이면 결측 → 화면 "공시에 기재 없음"
   - 인증 파싱 `parse_certs`: ISMS-P, ISMS, ISO 27001, ISO 27701, ISO 27017, ISO 27018, ISO 22301, PCI-DSS, CSAP, SOC 2. 한글 명칭도 인식함
     - "정보보호 및 개인정보보호 관리체계" → ISMS-P
     - "정보보호 관리체계" → ISMS. 단 앞에 "개인"이 붙은 경우는 ISMS-P 문구의 일부라 제외함
     - 클라우드 서비스 보안인증 → CSAP
   - `has_cert`: 인식한 인증이 1개 이상
3. `load_kisa_disclosure()`: 2개년을 읽어 합침. `select_targets(df, year, industry)`: 대상 회사, `company_id` = 이름키
4. 테스트
   - 가짜 데이터 단위 테스트 (원본 없이 돎)
   - 원본 회귀 테스트: 2026 826행·2025 773행, 제조업 387, 이름키 중복 0, `figures_in_attachment` 2026 16행·제조업 0행, 인증 건수

## 진행 기록

- 2026-09-28 사전 점검: IT 투자액 0/결측 17행, 투자항목 참조 문구, 인증 표기(영문·한글)를 원본에서 확인함 (입력 절 참고)
- 기준 연도 확인
  - KISA 포털 제도 안내: 제출 기한만 있음
  - 안랩 해설: "전년도 지출 내역" 점검 항목만 있음
  - 2차 해설 페이지: 403으로 열람 불가
  - → 확정하지 못함
- 회귀 기대값을 구현과 별도로 계산해 둔 뒤 테스트를 먼저 씀 (`tests/test_kisa.py` 37개)
  - 실행하니 `kisa` 모듈이 없어 실패함 → 기대한 실패
- 구현 후 두 가지 문제를 만나 고침
  - `-W error`에서 openpyxl의 "기본 스타일 없음" 경고가 오류가 됨 → 원본 읽기를 `pipeline/sources/common.py`(`read_excel`, `read_csv`)로 모으고 그 경고 하나만 숨김
  - 업종이 빈 6행 때문에 "업종 == 제조업" 비교에 NA가 섞여 합계에서 오류가 남 → 테스트와 `select_targets` 모두 결측을 명시적으로 거짓 처리함
- 원본 목록에서 `kisa_*` source_id를 자동으로 찾게 함 → 2027 공시 파일을 manifest에 추가만 하면 됨
