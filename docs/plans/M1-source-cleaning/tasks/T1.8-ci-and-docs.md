- M1에서 바뀐 사실을 문서에 반영해, 다음 단계(M2 Stitch 핸드오프)가 정확한 문서를 쓰게 함

## 입력

- 문서: `CLAUDE.md`, `docs/data-schema.md`, `docs/data-sources.md`, `README.md`

## 절차

1. 테스트 속도: `tests/conftest.py`에 세션 공용 fixture를 둠
   - `sources`: 원본 6종을 한 번만 읽음
   - `built`: 연간 빌드를 임시 폴더에 한 번만 실행함
   - 원본 회귀 테스트들이 이 fixture를 쓰게 바꿈
   - 연간 빌드 명령 테스트는 빌드 함수를 바꿔 끼워 명령 동작(인자 전달, 출력, 종료 코드)만 검사함. 실제 쓰기는 `built`가 검사함
2. `tests/test_repo_hygiene.py` (TDD)
   - `git ls-files`에 `data/raw/`의 원본(manifest 제외), `.env`, `data/cache/`, `.venv/`가 없음
   - 추적 중인 텍스트 파일에 40자리 영숫자·13자리 숫자 형태 문자열이 없음 (`data/raw/manifest.csv` 제외)
   - git이 없으면 건너뜀
3. `.github/workflows/ci.yml`
   - push·PR에서 Python 3.11, `requirements-pipeline.txt` 설치
   - `PYTHONUTF8=1 pytest -W error`
   - 원본이 없으니 원본 회귀는 건너뛰고, 정제 함수·결합 규칙·게이트·개인정보·저장소 위생 테스트가 돎
4. 문서
   - `docs/data-schema.md`: 6장을 M1 실제 테이블·주요 열로 바꾸고 임시 `company_id`를 설명함. 결합 수를 영문 표기 변환 반영 값으로 고침
   - `docs/data-sources.md`
     - KISA 투자항목·인증 인식 규칙, 업체코드 형식, 공장 주소 공백 1,880행
     - 5장 manifest 재생성 명령
   - `CLAUDE.md`: 빌드·manifest 명령, 코드 구조 현황, 회귀 기준값, 영문 표기 변환·SI 수동 보완
   - `README.md`: 현재 단계
5. 커밋·푸시 후 GitHub Actions 결과 확인
