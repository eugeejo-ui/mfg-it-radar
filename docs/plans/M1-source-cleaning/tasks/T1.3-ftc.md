# T1.3 공정위 정제 — 작업 계획서

- 상태: 완료
- 상위 문서: `docs/plans/M1-source-cleaning/phase-plan.md`

## 목적

- 공정위 소속회사 개요를 개인정보 없는 `group_membership`으로, 기업집단별 개요를 `business_group`으로 정제함
- 계열 SI(업종코드 J620 + 수동 보완)를 집단 단위로 정리해 "구매 경로" 판단 재료를 만듦
- 법인등록번호는 M3의 정확 결합을 위해 로컬 캐시로만 남김

## 입력

- `ftc_affiliates`, `ftc_groups` (manifest), `pipeline.normalize`, `pipeline.sources.common`
- 사전 점검 (2026-09-28)
  - 3,539행. (기업집단명, 소속회사명) 중복 0 → 한 행의 키로 씀
  - 이름키가 같은 서로 다른 법인 2쌍: '동림'(유진·하림), '동양에너지'(라인·유진) → T1.6 검수 대상
  - 계열 SI 행 49 = 고유 법인 49, 집단 37
  - 매출 "0" 600행, 빈칸 0행, 0보다 큼 2,924행
  - 자본총액 음수 443행, 당기순이익 음수 1,505행 → 음수는 정상 값으로 둠
  - 종업원수는 천 단위 쉼표 문자열 (쉼표를 빼면 모두 숫자)
  - 공개년월 `202605` 하나

## 절차 (TDD)

1. `clean_affiliates(raw)` → (`membership`, `jurir`)
   - `membership` 열
     - `disclosure_ym`(`2026-05`), `group_name`, `company_name`, `name_key`
     - `established`, `affiliated_on`, `listed_on`(날짜), `listed`(기업공개일 있음)
     - `industry_code`, `ksic2`, `industry_name`, `employees`, `fiscal_year_end`, `category`(구분)
     - 금액 `assets_krw`, `liabilities_krw`, `equity_krw`, `capital_krw`, `revenue_krw`, `net_income_krw`: 백만원 × 10⁶
     - `fs_div` = `OFS`(개별)
   - 매출 0은 결측으로 바꿈. 다른 금액의 0·음수는 그대로 둠
   - 버리는 열: 대표자, 사업자등록번호, 결산주총일
   - `jurir`: `group_name`, `company_name`, `name_key`, `jurir_no` → `data/cache/`에만 씀 (쓰기는 T1.7 빌드에서)
2. `clean_groups(raw)`
   - 열: `data_year`, `group_name`, `rank`, `n_affiliates`, `employees`, 금액 5종(`*_krw`, 백만원 × 10⁶)
   - 상장·비상장 소속회사수(전부 0)는 버림
3. `find_si(membership, manual=None)`
   - 업종코드가 J620으로 시작하는 회사 + 수동 목록(`data/manual/si_manual.csv`: `group_name`, `company_name`, `reason`)
   - 결과 열: `group_name`, `company_name`, `name_key`, `si_source`(`업종코드 J620` 또는 `수동`)
4. `load_ftc()`: 두 원본을 읽어 (`membership`, `jurir`, `groups`)를 돌려줌
5. 테스트
   - 가짜 데이터 단위 테스트
   - 원본 회귀: 3,539행, 법인 3,521, 집단 102(두 파일의 집단명 일치), 계열 SI 49개사·37개 집단, 상장 법인 389, 매출 결측 600, `membership`에 개인정보 열 없음
