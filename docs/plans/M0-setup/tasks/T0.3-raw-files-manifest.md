# T0.3 원본 파일 이관과 목록 — 작업 계획서

- 상태: 완료
- 상위 문서: `docs/plans/M0-setup/phase-plan.md`

## 목적

- Downloads에 흩어진 원본 10개 파일을 프로젝트 `data/raw/`로 모아, 원본이 지워지거나 바뀌어도 알아챌 수 있게 함
- 코드가 파일명 대신 source_id로 원본을 찾도록 목록(manifest)을 만듦

## 입력

- `C:\Users\조유신\Downloads`의 원본 10개 파일 (phase-plan 2장 표)
- 기획 단계 점검 결과 (행 수, 읽기 주의)

## 절차

1. 10개 파일을 이름 그대로 `data/raw/`에 복사함 (Git Bash `cp`). Downloads의 다른 파일은 건드리지 않음
2. 원본과 복사본의 sha256을 비교함
3. 파일마다 실제로 읽어 행 수를 셈. 읽는 방식은 점검 때와 같게 함
   - 배출권: `header=0, skiprows=[1]` (2행이 빈 행)
   - 산단공 CSV: cp949 (시도별 통계 4종도 인코딩을 확인함)
4. `data/raw/manifest.csv`를 UTF-8로 작성함
   - 열: `source_id, file_name, provider, portal_url, reference_date, encoding, sha256, bytes, rows, note`
   - `encoding`은 CSV만 적음. 정제 코드가 인코딩을 추측하지 않고 이 값을 씀
   - `rows`는 헤더 처리 후 데이터 행 수
   - `note`에 읽기 주의를 적음
5. 가상환경은 T0.4에서 만들므로, 이 작업의 행 수 계산은 Anaconda 파이썬으로 한 번만 돌림

## 산출물

- `data/raw/` 원본 10개 (커밋 안 됨)
- `data/raw/manifest.csv` (커밋됨)

## 검증 방법

- 원본과 복사본의 sha256이 10개 모두 같음
- 행 수가 기획 단계 점검값과 같음: kisa_2025 773, kisa_2026 826, ftc_affiliates 3,539, ftc_groups 102, ngms_emission 772, kicox_factories 217,048
- `git status`에 원본 파일은 나오지 않고 `manifest.csv`만 나옴

- CSV 5개의 인코딩을 확인함 → 모두 cp949
  - 시도별 통계 중 공장규모 파일만 광주·전남을 나눠 적었고, 나머지 3개는 '전남광주' 합산 열임 (SPEC 9장과 같음)
