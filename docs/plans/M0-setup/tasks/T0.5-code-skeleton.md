# T0.5 코드 골격과 테스트 실행 확인 — 작업 계획서

- 상태: 완료
- 상위 문서: `docs/plans/M0-setup/phase-plan.md`

## 목적

- 전체 계획 3장의 폴더 구조를 빈 패키지로 만들어, M1부터 파일을 제자리에 추가하기만 하면 되게 함
- pytest가 동작하는지, 원본 파일이 manifest와 일치하는지 자동으로 확인하는 테스트를 하나 둠

## 입력

- 전체 계획 3장 저장소 구조
- `data/raw/manifest.csv` (T0.3)
- `.venv` (T0.4)

## 절차

1. 빈 패키지 생성 (`__init__.py`만 둠, 기능 코드 없음)
   - `app/`, `app/pages/`, `app/blocks/`
   - `pipeline/`, `pipeline/sources/`, `pipeline/dart/`, `pipeline/jobs/`
   - `tests/`, `tests/fixtures/`(`.gitkeep`)
   - `app/pages/`는 Streamlit 페이지 파일을 두는 곳이라 `__init__.py` 없이 `.gitkeep`만 둠
2. `data/manual/`, `data/processed/`에 `.gitkeep`
3. `pytest.ini`
   - `testpaths = tests`
   - `live` 마커 등록, 기본 실행에서 제외(`-m "not live"`)
4. `tests/test_raw_manifest.py`
   - manifest의 모든 행에 대해 `data/raw/<file_name>`이 있고 sha256·크기가 같은지 확인
   - `data/raw/`에 원본이 하나도 없으면(CI·Actions) 건너뜀
   - manifest 자체는 항상 검사함: 필수 열 존재, source_id 중복 없음
5. `.venv\Scripts\python -m pytest -v` 실행

## 산출물

- 빈 패키지 폴더들, `pytest.ini`, `tests/test_raw_manifest.py`, `.gitkeep` 파일들
