# T0.7 OpenDART 키 발급·보관 안내 — 작업 계획서

- 상태: 진행 중
- 상위 문서: `docs/plans/M0-setup/phase-plan.md`
- 순서 변경: 안내 문서를 첫 커밋에 넣으려고 T0.6보다 먼저 수행함

## 목적

- 사용자가 OpenDART 키를 발급받아 로컬과 GitHub에 안전하게 넣는 절차를 한 문서로 정리함
- 키 값이 대화, 문서, 커밋, 로그 어디에도 남지 않게 함

## 입력

- 설계 검토에서 확인한 DART 사항: 호출 한도 약 2만 건(초과 시 020 오류), 1인 1키 원칙(이용약관 19조 5항)
- `.env.example` (T0.4), `.gitignore`의 `.env` 제외 규칙 (T0.1)
- gh CLI 로그인 상태 (eugeejo-ui, repo·workflow 권한)

## 절차

1. `docs/guides/dart-api-key.md` 작성
   - 발급: OpenDART 누리집에서 인증키 신청 → 메일 인증 → 인증키 확인
   - 로컬 보관: `.env.example`을 `.env`로 복사하고 사용자가 값을 직접 입력
   - GitHub 보관: 저장소 생성(T0.6) 후 사용자가 `gh secret set DART_API_KEY`를 실행해 프롬프트에 붙여 넣거나 웹 설정 화면에서 등록
   - 하지 말 것: 대화창 붙여 넣기, 코드·문서에 쓰기, 커밋, 스크린샷 공유
   - 동작 확인은 M3 첫 작업에서 함 (응답 상태 코드만 출력)
2. 확인되지 않은 내용(메뉴 이름, 재발급 가능 여부)은 단정하지 않고 그렇게 적음

- M3
