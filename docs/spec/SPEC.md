# 기업 IT 투자 레이더 (가칭) — 화면설계 명세

## 0. 이 문서의 용도

- Claude Code가 화면설계를 진행할 때 참조하는 명세임
- 확정 사항, 기본 가정(변경 가능), 미결정 사항을 구분해 적음
- 8장 수치는 2026.9 원본 파일 점검 결과이며, 회사명 단순 정규화 매칭 기준이라 실제 결합 후 달라질 수 있음

## 1. 서비스 개요

- 국내 공개 데이터를 결합해 기업별 IT·보안 투자 수준, 구매 경로, 규제 노출, 생산 거점, 최근 투자 신호를 한 화면에서 보여주는 서비스임
- 비영리 공개 서비스임. 로그인, 결제, 광고 등 수익화 기능 없음
- 재무·신용 조회는 기존 상용 기업정보 서비스가 이미 제공함. 이 서비스의 차별점은 IT 예산, 계열 SI 여부, 규제 노출을 영업 관점으로 묶는 부분에만 있음 → 화면에서도 이 세 가지를 앞에 둠

## 2. 사용자

- 기본 가정(변경 가능): 주 사용자는 B2B IT·보안 솔루션 회사의 신규 고객 발굴·자격검증 담당임 (인사이드 세일즈, 파트너·리셀러 영업, 영업기획)
- 보안 솔루션 영업이 가장 직접적인 신호를 얻음 (CISO 겸직, 외부 보안인력, 인증, 투자 품목)
- 데이터·AI 솔루션 영업에게는 IT 투자 총액과 인력 정도만 쓸모가 있어 신호가 상대적으로 약함
- 보조 사용자: 기업 CISO·IT기획 담당. 자사 투자 수준을 동종업계와 비교해 예산 근거로 씀
- 대형 벤더의 계정 담당 영업은 사내 고객 자료가 있어 우선순위 낮음
- 사용 빈도: 핵심 데이터(정보보호 공시)가 연 1회 갱신이라 분기·연 단위로 쓰는 도구임. 재방문 유도는 최근 공시 신호(DART)가 담당함

## 3. 사용자 과업과 화면

| 사용자 과업 | 화면 |
|---|---|
| 아직 거래 없는 회사 중 어디부터 갈지 정함 | 후보 목록 (필터) |
| 한 회사가 우리 제품에 맞는지 확인함 | 기업 브리프 (메인) |
| 동종업계 대비 어느 수준인지 봄 | 기업 브리프 내 벤치마크 블록 (CISO 사용자는 여기서 시작) |
| 최근 이 회사에 무슨 일이 있었는지 봄 | 기업 브리프 내 최근 공시 블록 |
| 숫자가 어디서 왔는지 확인함 | 데이터 출처·기준일 |

## 4. 화면 명세

### 4.1 기업 브리프 (메인)

- 입력: 회사명 검색 (정규화된 이름 기준 자동완성)
- 블록 순서 (2장 기본 가정 사용자 기준, 사용자 확정 시 조정):
  1. 요약 헤더: 회사명, 업종(대분류·세부), 기업집단 소속, 상장 여부, 데이터 기준일
  2. IT 여력: IT 투자액, 전년 대비 증감률, IT 투자/매출, IT 인력 비중
  3. 구매 경로: 기업집단명, 계열 SI 보유 여부와 회사명 → 직접 영업 가능 계정인지, 계열 SI 경유 계정인지 판단 재료
  4. 보안 성숙도: 보안 투자 비중(B/A), CISO 임원·겸직 여부, 외부 보안인력 사용 여부, 보유 인증 목록
  5. 투자 품목: 주요 투자항목 원문 + 키워드 태그. 값 없으면 "공시에 기재 없음"
  6. 동종업계 벤치마크 (4.2)
  7. 규제 노출: 배출권 할당대상 여부, KSIC 코드
  8. 생산 거점: 공장 수, 시도 분포, 산업단지 입주 공장 수, 대표 생산품 (2024.12 기준 명시)
  9. 최근 공시 신호: 최근 90일 DART 공시 중 보고서명 키워드 해당 건 (신규시설투자, 유형자산 양수, 타법인 주식 취득, 합병 등). 보고서명, 날짜, 원문 링크
  10. 재무: 매출·영업이익 3개년. 연결/개별 기준 라벨 필수

### 4.2 동종업계 벤치마크

- 지표: IT 투자액, IT 투자/매출, IT 인력 비중, 보안 투자 비중
- 비교 그룹: 세부업종 × 규모 구간 (임직원 300명 이하 / 300~1,000 / 1,000~3,000 / 3,000 초과)
- 비교 대상이 10개 미만이면 규모 조건을 풂 → 그래도 10개 미만이면 대분류 업종으로 넓힘. 실제 적용된 그룹 조건을 화면에 표시함
- "비교 대상 N개사"를 항상 표시함
- IT 투자/매출은 매출을 확보한 기업끼리만 비교하고, 해당 N을 따로 표시함
- 표현: 분포 안에서 해당 회사 위치 (seaborn 분포 그래프 + 해당 회사 강조)

### 4.3 후보 목록

- 필터: 업종(대분류·세부), 규모 구간, IT 투자 증감(예: 20% 이상 증가), CISO 겸직, 외부 보안인력 사용, 인증 보유·미보유, 계열 SI 유무, 배출권 할당대상, 공장 다거점(2개 이상 시도), 최근 90일 공시 신호 있음
- 결과: 표 (회사명, 업종, 규모 구간, IT 투자액, 증감률, 해당 신호 태그). 행 선택 시 기업 브리프로 이동
- 점수·순위 부여 안 함 (5장). 정렬은 사용자가 열 기준으로 선택
- CSV 내려받기 제공

### 4.4 데이터 출처·기준일

- 파일별 출처 기관, 기준일, 다음 갱신 예상 시점, 알려진 한계(9장) 요약
- 매칭 방식 설명: 회사명 정규화 결합이라 오매칭 가능성이 있음을 고지함

## 5. 화면 설계 원칙 (확정)

- 적합도 점수 제공 안 함: 가중치를 정할 근거가 없어 점수가 설득력을 떨어뜨림. 신호를 나열하고 판단은 사용자에게 맡김
- 비교 대상 수를 항상 표시하고, 소수 비교는 자동 확대 규칙을 적용함 (4.2)
- 매출 기준 혼용 금지: 공정위 소속회사 매출은 개별 기준, DART 재무는 연결 기준일 수 있음 → 라벨로 구분하고 한 비율 계산에 섞지 않음
- 값 없음과 0을 구분함: 투자액·인력을 0으로 적고 "첨부 참조"만 남긴 회사는 "공시 원문 참조"로 표시함
- 모든 블록에 출처와 기준일을 표기함
- 대표자, 법인등록번호, 사업자등록번호는 화면에 노출하지 않음 (결합 키로만 사용)
- 그래프는 seaborn으로 그림
- 화면 문구는 사용자 언어로 씀 (예: "정보기술부문 투자액(A)" → "IT 투자액")

## 7. 결합 규칙

- 소속회사 개요 ↔ DART: 법인등록번호 = DART 기업개황의 법인등록번호(jurir_no). 정확 결합됨
- 그 외 결합은 회사명 정규화 후 결합하고, 수동 검수 테이블로 보완함
- 정규화 규칙:

```python
re.sub(r'\(주\)|㈜|주식회사|\(유\)|유한회사|유한책임회사|\s', '', name)
```

- 매칭 실패 목록은 파일로 남겨 사람이 검수함 (매년 갱신 때 반복되는 단계임)
- 계열 SI 판정: 소속회사 업종코드가 `J620`으로 시작하면 계열 SI로 봄. SK·포스코처럼 SI 역할 회사가 업종코드로 잡히지 않는 경우는 수동 목록으로 보완함

## 9. 데이터 품질 주의

- 정보보호 공시는 의무 대상(대형 상장사 등) 중심이라 대형사로 치우쳐 있음. 중견·중소 대표성 없음
- 자기신고 수치라 품질 편차 있음: 임직원 수가 소수점으로 적힌 행, 0 기재 + "첨부 참조" 행 존재
- 공장 결합은 이름만으로 하므로 동명 회사가 섞일 수 있음. 공장 수가 튀는 회사(예: 58개)는 확인 필요
- 공장규모 시도별 통계 파일은 라벨이 뒤바뀐 것으로 보임 (서울 "대기업" 10,785, "소기업" 18). 확인 전 사용 보류
- 시도별 통계 파일마다 지역 열 구성이 다름 (광주·전남 합친 파일과 나눈 파일이 섞여 있음)
- 기업집단 개요의 상장·비상장 소속회사수 열은 전부 0

## 10. 갱신 구조 (이번 화면설계 범위 밖, 화면의 기준일 표기에만 반영)

- 공정위 기업집단·소속회사: 공식 OpenAPI 있음. 매년 5월 1일 기준 공개. 공개년월 조회 API로 새 버전 감지. 재무 열이 같은 API에 있는지는 활용가이드 확인 필요
- 전국 등록공장: 공공데이터포털 파일 다운로드 또는 자동변환 API. 연간 갱신. 포털 설명상 종업원 수·업종코드가 포함된 버전이 있을 수 있어 확인 필요
- DART: API, 최근 공시는 일 단위 조회
- 정보보호 공시: API 없음. 매년 6월 30일 제출 → 7~8월 수동 반영. 2027년 공시부터 상장사 전체와 ISMS 인증 의무기업으로 대상 확대 추진 중 (2026.5 재입법예고 단계, 확정 여부 확인 필요). 확정 시 비교 대상이 크게 늘어 소수 비교 문제가 상당 부분 해소됨
- 배출권 할당대상: API 없음. NGMS 게시 자료를 수동 반영
- 자동화 방식: GitHub Actions 월 1회 실행 → 새 버전 확인 → 정제·매칭 → 결과 파일 저장 → Streamlit Community Cloud 재배포. API 키는 GitHub Secrets
- 공개 서비스이므로 화면마다 출처 표시

## 11. 기술 스택

- Python, Streamlit (멀티페이지), pandas, seaborn
- 정제 결과는 parquet 또는 SQLite로 저장
- 배포: Streamlit Community Cloud
- 디자인 조정은 `.streamlit/config.toml` 테마와 최소한의 CSS로 함

## 12. 디자인 방향 지침

- 구현 전에 디자인 계획을 먼저 씀: 색 4~6개(hex와 이름), 서체와 역할, 화면별 ASCII 와이어프레임과 정렬 방식, 설계 원칙
- 계획을 쓴 뒤 흔한 기본값이 섞였는지 점검하고 고침: 똑같은 둥근 카드의 반복, 모든 제목 위 대문자 라벨, 순서가 아닌데 붙인 번호 표식, 장식용 그라데이션
- 소재에 맞춤: 기업 공시·재무를 다루는 조회 도구라 숫자와 비교가 읽기 쉬운 것이 최우선임
- 강조는 한 곳에만 씀 (예: 기업 브리프의 IT 여력 블록). 나머지는 조용하게 둠
- 문구는 쉬운 말, 능동형으로 씀. 빈 결과·오류 화면은 다음에 할 행동을 안내함

## 13. 미결정 사항

- 주 사용자 확정 (보안 솔루션 영업 / IT 솔루션 발굴 영업 / 기업 CISO·IT기획) → 기업 브리프 블록 순서와 첫 화면이 달라짐
- 서비스명
- MVP 대상 범위: 기본 가정은 정보보호 공시 제조업 387개사 (매칭 검수 부담 관리 목적). 전체 826개사로 넓힐지 미정
