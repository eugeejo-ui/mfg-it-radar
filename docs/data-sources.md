# 원본 데이터 참조

- 원본 파일의 형식, 읽는 방법, 결합 키, 품질 문제를 원본별로 정리함
- 정제 코드(M1)는 이 문서와 `data/raw/manifest.csv`를 기준으로 씀. 코드는 파일명 대신 source_id로 원본을 찾음
- 수치는 2026-09-28 원본 파일에서 직접 확인한 값임 (pandas 3.0.6)
- 결합 경로와 정제 결과 테이블 설계는 `docs/data-schema.md`에 있음

- 이름으로 결합하는 원본은 SPEC 7장 정규화 규칙을 씀: `re.sub(r'\(주\)|㈜|주식회사|\(유\)|유한회사|유한책임회사|\s', '', name)` + 영문 대문자화 (`pipeline.normalize.name_key`)
- 원본마다 영문·한글 표기가 섞여 있음 (KISA `CJ제일제당` ↔ 공정위 `씨제이제일제당`) → 완전 일치가 없으면 영문 글자를 한글 발음으로 바꾼 키로 한 번 더 맞춤 (`translit_key`, 결합 규칙은 `docs/data-schema.md` 4장)

## 2. 엑셀 5개

### 2.1 KISA 정보보호 공시 이행 기업 리스트 (kisa_2025, kisa_2026)

- 제공: KISA 정보보호 공시 종합포털 (https://isds.kisa.or.kr)
- 갱신: 매년 6월 30일 제출 → 7~8월 수동 반영. API 없음
- 시트: `2025`, `2026` (파일마다 1개). 두 연도의 열 30개가 같음
- 행: 2025 773행(의무 666, 자율 107), 2026 826행(의무 686, 자율 140, 제조업 387)
- 키: 없음. 기업명만 있음. 2026은 이름 정규화 후 중복 0
- 연도 연결: 2025↔2026 이름 일치 737/826. 나머지 89곳은 신규 공시와 회사명 변경이 섞여 있음 → corp_code 결합 후 판별
- 투자·인력 수치가 공시연도의 전년 실적인지 확정하지 못함
  - KISA 포털 제도 안내에는 제출 기한(매년 6월 30일)만 있음
  - "직전 연도 1~12월 기준"이라는 설명은 2차 자료에만 있음
  - → M4에서 IT 투자/매출을 만들기 전에 공시 가이드라인 원문으로 확인함 (T1.2)

열 구성

| 묶음 | 열 | 화면 용어 |
|---|---|---|
| 기본 | 공시연도(yyyy), 기업명, 업종, 자율/의무, 사전점검 수행여부 | 업종 대분류 |
| 투자 | 투자현황_정보기술부문 투자액(A), 투자현황_정보보호부문 투자액(B), 투자현황_주요 투자항목, 투자현황_비율(B/A), 투자현황_특기사항 | IT 투자액, 보안 투자액, 투자 품목, 보안 투자 비중 |
| 인력 | 인력현황_총임직원, 인력현황_정보기술부문 인력(C), 인력현황_정보보호부문 내부인력, 인력현황_정보보호부문 외부인력, 인력현황_정보보호부문 인력(D), 인력현황_비율(D/C), 인력현황_특기사항 | 임직원 수, IT 인력, 보안 인력(내부·외부) |
| 책임자 | 인력현황_CISO_직책명·임원여부·겸직여부·주요활동건수, 인력현황_CPO_직책명·임원여부·겸직여부·주요활동건수 | CISO·CPO 임원·겸직 |
| 인증·활동 | 정보보호 관련 인증·점검·평가 등에 관한 사항, 정보보호 활동 현황 | 보유 인증 |
| 표시 | 정보보호 공시 우수기업, 정보보호 투자우수기업 여부, 수정공시 여부 | 투자우수기업 |

값 형식
- 금액: 원 단위 float → 화면은 억원
- 비율(B/A), 비율(D/C): 퍼센트 숫자 (9.4는 9.4%)
- 여부 열: `O` / `X`
- 총임직원: 826행 중 652행이 소수(예: 3511.1). 연평균 인원으로 보임 → 규모 구간은 반올림 값으로 정함
- 업종: `제조업(10~34)` 형태 → 괄호를 떼서 "제조업"으로 표시. 2026 결측 6행
- 인증: 자유 기재 문자열 (예: `ISMS-P(정보보호 및 개인정보보호 관리체계)`, `○ ISMS(정보보호 관리체계)`)
  - 표기 분포: 영문 코드 387행, 한글 명칭만 32행, "해당 없음"류 220행, 결측 82행
  - 인식하는 인증(`kisa.parse_certs`): ISMS-P, ISMS, ISO 27001, ISO 27701, ISO 27017, ISO 27018, ISO 22301, PCI-DSS, CSAP, SOC 2
  - 한글 명칭도 인식함: "정보보호 및 개인정보보호 관리체계" → ISMS-P, "정보보호 관리체계" → ISMS, 클라우드 서비스 보안인증 → CSAP
  - 주의: ISMS-P의 한글 명칭 안에 "정보보호 관리체계"가 들어 있음 → 앞에 "개인"이 붙은 경우는 ISMS로 세지 않음
  - 2026 인식 결과: 인증 보유 419곳(제조업 127). ISO 27001 238, ISMS 230, ISMS-P 111, ISO 27701 70, ISO 27017 36, PCI-DSS 32, ISO 27018 26, CSAP 17, SOC 2 13, ISO 22301 7

품질 문제와 정제 규칙 (2026 기준)
- IT 투자액이 0이거나 결측: 17행 (제조업은 0행)
  - 대부분 글로벌 기업(Google, Microsoft, Oracle 등)이 한국 법인 수치 대신 설명문을 적음
  - 16행은 `figures_in_attachment`로 표시하고, 투자액·인력 수치를 결측으로 바꿈 (가짜 0이 벤치마크에 섞이지 않게)
  - 판정: 투자액 결측, 또는 0이면서 총임직원 0·결측이거나 특기사항에 첨부·참조·참고·추가 기재·글로벌 문구가 있음
  - 1행은 실제 0(임직원 5명, "현 단계 정보보호 투자가 없음")이라 0으로 둠
- 주요 투자항목
  - 결측 373행
  - 자리표시 `0`, `-`, `.`, `없음`, `해당사항 없음`은 결측으로 바꿈 → 화면 "공시에 기재 없음"
  - 첨부·참조·참고·추가 기재를 가리키는 7행은 `items_in_attachment` → 화면 "공시 원문 참조"
  - 제조업 387곳 중 실제 품목이 적힌 곳은 216곳
- 투자 품목 키워드가 보안 쪽으로 치우침 (품목 448건 중 보안 310, 일반 IT 180, 기획 단계 집계) → IT 전체 구매 내역으로 보지 않음
- `정보보호 공시 우수기업` 열은 826행 모두 `X` → 읽을 때 버림

읽는 코드

```python
from pipeline.sources import kisa
disclosure = kisa.load_kisa_disclosure()          # manifest의 kisa_* 원본을 모두 읽어 합침
targets = kisa.select_targets(disclosure, 2026, "제조업")
```

쓰이는 곳: 후보 목록 필터, 기업 브리프의 IT 여력·보안 성숙도·투자 품목·벤치마크

### 2.2 공정위 소속회사 개요 (ftc_affiliates)

- 제공: 공정거래위원회 기업집단포털 (https://www.egroup.go.kr), 공개년월 2026-05
- 갱신: 매년 5월 1일 기준 공개. 공식 OpenAPI 있음
- 시트: `소속회사 개요`
- 행: 3,539행 = 법인등록번호 기준 3,521개사 + 두 집단에 동시 소속된 18개사의 추가 행 (예: 애경산업은 태광·애경, 씨텍은 롯데·엘지)
- 키: 법인등록번호 13자리(결측 0), 사업자등록번호 10자리(결측 0) → DART 기업개황 jurir_no와 정확 결합
- 102개 기업집단

열 구성 (21개)
- 공개년월, 기업집단명, 소속회사명, 설립일, 계열편입일, 업종코드, 영위업종, 종업원수, 결산기일, 결산주총일, 기업공개일
- 재무: 자산총액, 부채총액, 자본총액, 자본금, 매출액, 당기순이익
- 구분, 법인등록번호, 사업자등록번호
- 대표자
- 비노출: 대표자, 법인등록번호, 사업자등록번호. 대표자·사업자등록번호는 읽은 직후 버리고, 법인등록번호는 결합 확인에만 씀

값 형식
- 모든 열을 문자열로 읽음 (법인등록번호 앞자리 보존)
- 날짜: `YYYY/MM/DD` 문자열 (설립일, 계열편입일, 결산기일, 기업공개일)
- 금액: 쉼표가 든 문자열(예: `56,237`), 단위 백만원, 개별 기준
- 매출액 `"0"`: 600행 → 값 없음으로 봄 (대상과 결합된 소속회사는 모두 0보다 큼). 자산·부채·자본금의 0과 자본총액(음수 443행)·당기순이익(음수 1,505행)의 음수는 그대로 둠
- 종업원수: 천 단위 쉼표가 든 문자열 (쉼표를 빼면 모두 숫자)
- 이름키가 같은 서로 다른 법인 2쌍: '동림'(유진·하림), '동양에너지'(라인·유진) → 대상과 결합되면 검수 필요로 둠
- 업종코드: 영문 대분류 + 숫자 4자리(예: `C2011`, `J6201`), 3,539행 모두 이 형식
  - 세부업종(KSIC 중분류)은 숫자 앞 2자리
  - 계열 SI: 업종코드가 `J620`으로 시작 → 49개사, 37개 집단
  - 업종코드로 잡히지 않는 SI 역할 회사는 `data/manual/si_manual.csv`로 보완함 (현재 에스케이(주) K6499, (주)포스코디엑스 M7212 → SI 보유 집단 38개)
- 구분: 일반회사 3,109 / 금융보험업 423 / 회생절차 5 / 공기업 1 / 워크아웃 1 → 상장 여부가 아님
- 상장 여부: 기업공개일에 값이 있으면 상장 (중복 제거 후 389개사)

읽는 코드

```python
from pipeline.sources import ftc
membership, jurir, groups = ftc.load_ftc()   # jurir(법인등록번호)는 data/cache/에만 씀
si = ftc.find_si(membership, manual)          # manual = data/manual/si_manual.csv
```

쓰이는 곳: 구매 경로(기업집단, 계열 SI), 세부업종, 상장 여부, 개별 매출(IT 투자/매출)

### 2.3 공정위 기업집단별 개요 (ftc_groups)

- 제공: 공정거래위원회 기업집단포털, 자료시점 2026
- 시트: `기업집단별 개요`
- 행: 102행, 한 행 = 기업집단
- 키: 기업집단명. 소속회사 개요의 `기업집단명` 102개와 완전히 일치함

열 구성 (13개)
- 자료시점, 기업집단, 순위, 소속회사수, 상장소속회사수, 비상장소속회사수, 상시종업원수
- 자산총액, 공정거래위원회자산총액, 부채총액, 자본총액, 매출금액, 당기순이익금액

값 형식
- 순위(1~102), 소속회사수: 정수
- 상시종업원수와 금액 열: 쉼표가 든 문자열
- 금액 단위는 파일에 적혀 있지 않음. 값 크기로 보아 백만원임 (예: BGF 자산총액 `6,543,334` ≈ 6.5조원)
- 상장소속회사수·비상장소속회사수: 102행 모두 0 → 쓰지 않음

쓰이는 곳: 구매 경로 블록의 집단 순위·규모

### 2.4 배출권거래제 할당대상업체 현황 (ngms_emission)

- 제공: 온실가스종합정보센터 국가온실가스종합관리시스템(https://ngms.gir.go.kr), 2026-01-01 기준
- 갱신: 게시 자료를 수동 반영. API 없음
- 시트: `sheet`
- 행: 772개 업체 (엑셀 2행의 빈 행을 뺀 값)
- 키: 업체코드는 I 506, E 131, M 99, F 29, S 7곳으로 시작하는 11자리 문자(예 `E0036120001`, `IA001200001`)이고 NGMS 내부 코드라 다른 원본에 없음 → 업체명으로 결합. 이름 정규화 후 중복 0
- 결합 결과(기획 단계, 완전 일치): 정보보호 공시 186곳(제조업 142), 소속회사 개요 239곳. M1 빌드(영문 표기 변환 포함)에서 대상과 결합 145곳

열 구성: (빈 첫 열), NO(1~772), 업체코드, 업체명, KSIC 코드

값 형식
- KSIC 코드가 숫자형으로 저장되어 있어 앞자리 0이 빠진 4자리 값이 3건 있음 (`5100`, `7110`) → 5자리로 채움 (`05100`)
- KSIC 5자리 = 세세분류. 세부업종(중분류)은 앞 2자리
- 772곳 중 KSIC 10~34(제조업) 451곳

읽는 코드


  - 열: 순번, 회사명, 단지명, 생산품, 공장주소
  - 한 행 = 공장, 이름 정규화 후 고유 회사명 151,227개
  - 단지명이 비어 있으면(공백 한 칸) 산업단지 밖 → 산업단지 입주 84,111행(38.8%)
  - 시도: 공장주소 첫 단어를 허용된 표기와 통째로 비교해 짧은 이름(서울, 경기, …, 제주)으로 바꿈 (`factory.sido_from_address`)
    - 변형 표기 `강원도`, `전라북도`, `제주특별자치`, `제주도`, `세종특별자치시,`도 인식함
    - `경기동로`처럼 시도 이름으로 시작하는 도로명이 있어 앞 글자만 보고 판단하지 않음
    - 시도를 알 수 없는 행 1,978개 = 주소가 공백 문자뿐인 행 1,880 + 도로명으로 시작하는 행 98
  - 동명 회사가 섞임: '대원산업' 한 이름에 공장 58곳·11개 시도·생산품 54종 → 이름 하나에 공장 20곳 이상이면 동명 의심 (`docs/data-schema.md` 4장)
  - 원본 읽기·정제에 약 5초 (21만 행)
- 시도별 통계 4종 (공장규모·공장면적·공장상태·업종별)
  - 열: 년월, 등록현황, 시도들
  - 기업 결합 불가, 지역 맥락용
  - 공장규모 파일만 광주·전남을 나누고, 나머지 3개는 '전남광주' 합산 열임

## 5. 원본을 새로 받을 때

1. 새 파일을 `data/raw/`에 넣음
2. `manifest.csv`에 새 파일 행을 추가하거나 파일명을 고친 뒤 `python -m pipeline.manifest refresh`로 sha256·크기를 다시 씀. `python -m pipeline.manifest check`로 확인함
3. 이 문서의 행 수·형식·품질 문제를 새 파일 기준으로 다시 확인하고 고침
4. `python -m pipeline.jobs.annual --check`로 빌드·검증만 해 봄 → 문제가 없으면 `python -m pipeline.jobs.annual`로 씀
5. `pytest`로 무결성 테스트와 회귀 테스트를 돌림. 기준값이 바뀌면 이유를 단계 계획서에 기록함
6. `data/processed/review_queue.csv`를 보고 필요한 결합을 `data/manual/xwalk_overrides.csv`에 적음
