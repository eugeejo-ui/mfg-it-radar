# 문서 체계

- 이 프로젝트의 문서 종류, 위치, 작성·갱신 시점, 이름 규칙을 정함
- 새 문서를 만들거나 기존 문서를 고칠 때 이 문서를 따름

## 1. 문서 종류

| 종류 | 위치 | 담는 내용 | 처음 쓰는 때 | 고치는 때 |
|---|---|---|---|---|
| 서비스 명세 | `docs/spec/SPEC.md` | 처음 받은 요구사항 원문 | 기획 시작 | 고치지 않음. 달라진 결정은 전체 계획 11장에 적음 |
| 전체 계획 | `docs/plans/00-master-plan.md` | 확정된 결정, 시스템 구성, 파이프라인, 자동 갱신, 마일스톤, 검증 방법 | 기획 승인 | 결정이 바뀔 때. 11장 변경 이력에 날짜와 내용을 남김 |
| 단계 계획서 | `docs/plans/M<n>-<이름>/phase-plan.md` | 목적, 넘겨받은 것, 범위, 작업 목록, 완료 기준, 위험 → 진행 기록, 결과, 다음 단계 연결 | 단계 시작 전 (사용자 승인 필요) | 진행 중 기록, 단계 종료 시 결과 |
| 작업 계획서 | `docs/plans/M<n>-<이름>/tasks/T<n>.<m>-<이름>.md` | 목적, 입력, 절차, 산출물, 검증 방법 → 진행 기록, 결과, 다음 작업에 넘기는 것 | 작업 시작 전 | 작업 종료 시 |
| 원본 데이터 참조 | `docs/data-sources.md` | 원본별 형식, 읽는 코드, 결합 키, 품질 문제 | M0 | 원본을 새로 받을 때 (연 1회) |
| 결합 스키마 | `docs/data-schema.md` | 결합 경로, 회사 1곳당 확보 정보, 정제 결과 테이블 설계 | 기획 | 테이블이나 결합 규칙이 바뀔 때 |
| 가이드 | `docs/guides/*.md` | 사람이 직접 따라 하는 절차 (예: DART 키 발급) | 필요할 때 | 절차가 바뀔 때 |
| Stitch 핸드오프 | `docs/stitch/` | 화면 디자인용 프롬프트와 맥락 md | M2 시작 | M2 진행 중 |
| 원본 목록 | `data/raw/manifest.csv` | 원본 파일의 source_id, 출처, 기준일, 인코딩, sha256, 행 수 | M0 | 원본을 교체할 때 |
| 프로젝트 규칙 | `CLAUDE.md` | 세션 공통 명령, 구조 요약, 규칙 | M0 | 명령·구조·규칙이 바뀔 때 |

## 2. 작성 흐름

```
단계 계획서 작성 ─▶ 사용자 승인 ─▶ 작업 계획서 작성 ─▶ 작업 실행 ─▶ 작업 결과 기록
                                        ▲                                  │
                                        └──────── 다음 작업 ◀───────────────┘
모든 작업 종료 ─▶ 단계 결과·다음 단계 연결 기록 ─▶ 다음 단계 계획서 작성
```

- 작업 계획서는 실행 전에 저장함. 실행 중 계획과 달라지면 진행 기록에 이유를 적음
- 결과에는 완료 기준 대비 판정과 근거(명령 결과, 수치)를 적음
- "다음 단계로 이어지는 내용"에는 넘기는 산출물, 남은 문제(담당·기한), 다음 단계의 선행 조건을 적음
- 계획에 없던 작업이 생기면 다음 번호로 작업 계획서를 만들고 단계 계획서의 작업 목록과 진행 기록에 추가함 (예: T0.8)

## 3. 이름 규칙

- 단계 폴더
  - `M0-setup`, `M1-source-cleaning`, `M2-screens-v0`, `M3-dart-matching`
  - `M4-financials-benchmark`, `M5-filings-daily`, `M6-monthly-hardening`
- 작업 파일: `T<단계>.<번호>-<영문-짧은-이름>.md` (예: `T0.3-raw-files-manifest.md`)
- 폴더·파일 이름은 영문으로 씀 (한글 경로가 도구에서 깨지는 사례가 있음). 본문은 한국어로 씀
- 양식: `docs/plans/_templates/phase-plan.md`, `docs/plans/_templates/task-plan.md`

## 4. 상태와 문체

- 상태 표기: 계획 / 진행 중 / 완료 / 보류. 문서 맨 위 `- 상태:` 줄에 적음
- 문체: 개조식 어미(~함, ~임)
- 수치는 직접 확인한 값만 적고, 확인하지 못한 내용은 확인하지 못했다고 적음
- 원본 파일명, 명령, 열 이름은 백틱으로 감쌈
